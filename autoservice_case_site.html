Целостность данных

  • Первичные ключи однозначно идентифицируют каждую запись.
  • Внешние ключи исключают заказ без автомобиля или механика.
  • Проверки ограничивают статусы, цены, остатки и количество.
  • Уникальные ограничения применены к VIN, поставщикам, артикулам и платежам.

Запросы по кейсу

В едином SQL-файле находятся DML-операции, выборки, агрегаты, девять JOIN-запросов, пять подзапросов и представление.

SELECT status, COUNT(*) AS orders_count,
       SUM(total_cost) AS total_amount,
       ROUND(AVG(total_cost), 2) AS avg_order_amount
FROM repair_orders
GROUP BY status
HAVING COUNT(*) > 10
ORDER BY total_amount DESC;

Показывает количество и стоимость заказов по каждому статусу, включая средний чек.

SELECT o.order_id, c.full_name AS client,
       v.license_plate, m.full_name AS mechanic, o.total_cost
FROM repair_orders o
JOIN vehicles v ON v.vehicle_id = o.vehicle_id
JOIN clients c ON c.client_id = v.client_id
JOIN mechanics m ON m.mechanic_id = o.mechanic_id
ORDER BY o.order_date DESC;

Соединяет четыре таблицы и формирует карточку заказ-наряда с ответственным механиком.

SELECT order_id, status, total_cost
FROM repair_orders
WHERE total_cost > (
  SELECT AVG(total_cost) FROM repair_orders
)
ORDER BY total_cost DESC;

SELECT * FROM v_completed_orders LIMIT 10;

Первый запрос находит дорогостоящие ремонты; второй обращается к VIEW с завершёнными и оплаченными заказами.
